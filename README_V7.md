# OntoTutor 7.0 — поиск по графу и ответы из семантических троек

## Что изменено

* Поиск по длинным названиям: «алгоритм обратного распространения» не должен заменяться корневым «Алгоритм» из-за совпадения одного слова.
* Совпадения ранжируются с учётом словоформ, полного и частичного состава терминов, опечаток, TF-IDF и расстояния до текущего узла в графе. Часть в скобках считается поисковым вариантом. Для каждой загруженной онтологии индекс строится заново.
* Для каждого отношения ONTOLIS формируется направленная тройка `subject — predicate — object`, не теряющая направление исходной стрелки.
* Вопросы о составе, применении, видах, входах, выходах и принципе работы выбирают относящиеся к типу вопроса тройки. В ответе отображаются исходный вопрос, определение из атрибута узла и связное объяснение по найденным рёбрам. Программа не придумывает факты, которых нет в онтологии.
* Для вопросов «как работает» учитывается второй уровень вложенных составляющих. Для вопросов о назначении общей категории могут использоваться явно обозначенные отношения её конкретных видов/экземпляров (не более двух переходов).
* В активной учебной сессии разрешён переход к следующему **соседнему узлу** DFS-маршрута по явно названному понятию. Переходы на удалённые шаги, не идущие следующими, по-прежнему не засчитываются.
* Дополнительный API `GET /api/ontologies/{ontology_id}/triples?node_id=49&depth=2` отдаёт связанные тройки с ID узлов и связей. Параметр `node_id` необязателен; без него выводятся тройки всей онтологии (с лимитом, по умолчанию 250).
* Распространённые эквивалентные названия типов отношений (`is_instance_of`, `instance_of`, `part_of`, `has_part`, `uses`) автоматически сопоставляются с типовыми ролями. Для нестандартных отношений предусмотрена прежняя ручная настройка учебных ролей.

## Что не изменилось

* HTML, CSS и JavaScript интерфейса сохранены без изменений.
* Определения не записаны в коде: источник — **атрибуты каждой загруженной `.ont`**. Скрипт загрузки определений из DOCX остался прежним.
* Учебные сессии сохраняются в оперативной памяти сервера, то есть исчезнут после перезапуска.
* В новой версии не используется генеративная LLM. TF-IDF — лексико-статистическое представление, а не нейросетевой семантический эмбеддинг. Нейросетевые эмбеддинги остаются необязательными и требуют заранее установленной локальной модели.

## Ограничения

Это детерминированная QA-система на структурированных данных, **не чат-бот уровня ChatGPT**. Она не сможет достоверно отвечать на любой произвольный вопрос без соответствующих определений, отношений и/или синонимов в онтологии. Назначение неизвестных отношений не угадывается: укажите учебную роль в панели приложения. В неоднозначных случаях выводятся варианты для уточнения. Получаемые ответы не заменяют логическое доказательство полноты или непротиворечивости предметной области.

## Установка и тестирование

Windows: запустить `start_windows.bat`, затем открыть страницу, указанную в консоли. Для первого запуска требуются Python и доступ в интернет, чтобы установить зависимости. Альтернативно:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app:app --reload
```

Тесты:

```powershell
pip install pytest httpx python-docx
python -m pytest -q
```

Проверялись: оригинальная ONTOLIS-онтология, другая предметная область, альтернативные названия в скобках, иерархия `Алгоритм → Алгоритм обучения → Алгоритм обратного распространения`, поиск опечаток, исходные направления троек, ответы по связанным узлам и API. На момент сборки пройдено 50 из 50 тестов.

**Важно:** новое понятие «Алгоритм обучения», добавленное пользователем позднее, отсутствовало в доступной исходной архивной онтологии. Проверка проводилась на отдельной синтетической онтологии с такой же структурой. Чтобы использовать фактические новые определения и связи, загрузите ваш обновлённый файл ONTOLIS в приложение.

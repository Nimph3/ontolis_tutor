# OntoTutor v6 — QA-система, управляемая онтологией ONTOLIS

## Основной принцип

Определения понятий **не хранятся в исходном коде**. Источник определений — таблица DOCX; `script.py` добавляет значения в `nodes[].attributes.definition` файла `.ont`. Веб-приложение читает только определения из активной онтологии. Формулировки и связи не дополняются из знаний LLM. Для прежних файлов поддерживаются атрибуты `def`, `Определение`, `description` (чтение, без изменения исходного файла).

Для демонстрационного графа по нейросимулятору использовано 54 узла и 99 связей. Из DOCX однозначно сопоставлены **53 определения**. Для узла 60 «Математическая модель» отдельного определения в источнике нет: поле оставлено незаполненным. Оба узла «Функция активации» (65 и 208) получили определение из документа. Связи 231 и 236 отдельно восстановлены как `input` по ранее согласованному решению пользователя; импортёр определений сам типы связей не исправляет.

## Запуск веб-приложения

На Windows можно дважды нажать **`start_windows.bat`**. При первом запуске скрипт автоматически создаёт `.venv`, устанавливает Python-зависимости и открывает приложение в браузере `http://127.0.0.1:8000`. Требуется установленный Python 3.10+ и интернет для первичной установки зависимостей. В дальнейшем программа работает локально без интернет-соединения (если зависимости уже установлены). **Это не готовый облачный сервис:** на произвольном компьютере без Python она пока не запускается. Для запуска только браузером нужен отдельный серверный деплой.

Или вручную:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python start_web.py
```

## Повторный импорт определений из документа

Обновите DOCX, затем запустите скрипт (из папки `ontolis_tutor`):

```powershell
python -m pip install -r requirements-import.txt
python script.py --ont sources/ontology_without_definitions.ont --docx sources/definitions_original.docx --overrides tools/definition_matches.csv --out ontology_new.ont --report definitions_report.csv
```

`--overrides` необязателен и содержит **только соответствия названия и категории, но не определения**. В текущем комплекте он разрешает неоднозначность двух персептронов (модель / метод), не подменяя текст документа.

У любого нового DOCX должна быть таблица с колонками «Понятие», «Определение» и, по возможности, «Категория». Если в документе несколько разных определений одного понятия, скрипт не выбирает наугад, а фиксирует `ambiguous` в CSV. При повторном импорте значение `definition` обновляется из нового DOCX (исправление источника переносится автоматически). В имеющемся DOCX определение «Математическая модель» отсутствует — добавьте отдельную строку в Word, чтобы заполнить 54-й узел.

### Загрузка произвольной ONTOLIS

Нажмите «Загрузить .ont». Требуется валидный JSON-экспорт ONTOLIS с массивами `nodes` и `relations`, узлами `{id,name,attributes:{definition:"..."}}`, связями `{id,name,source_node_id,destination_node_id}`. Данные новой предметной области не содержатся в Python-коде. Стандартные типы `is_a`, `is_instance`, `has`, `a_part_of`, `use`, `used_for`, `input`, `output`, `same_as` распознаются автоматически; для новых имён отношений задайте роль в панели «Настроить типы связей».

### NLP и поиск

- Токенизация, Unicode-нормализация, приведение к нижнему регистру: `question_processing.normalize()`.
- Морфологическая нормализация: `question_processing.lemma()`; `pymorphy3` при установленном модуле, иначе резервный упрощённый стемминг (результаты могут различаться).
- Генерация поисковых вариантов по **любой** онтологии: `ontology_search.term_variants()` (названия, скобки, части имени, сокращения, именованные атрибуты-синонимы).
- Поиск по названиям и определениям, исправление опечаток: `OntologySearch.lookup()` (`rapidfuzz`, совпадения токенов, TF-IDF).
- Косинусная близость TF-IDF-векторов: `TfidfVectorizer` + `cosine_similarity` из scikit-learn. Это **лексическое векторное представление, не нейросетевые эмбеддинги**.
- Семантические эмбеддинги: **опционально**, если установлен `sentence-transformers` и указан путь локальной модели в переменной `ONTOTUTOR_EMBEDDING_MODEL`. Без скачанной модели на ПК нейросетевые эмбеддинги не используются. Не требуется сеть во время запроса.
- Анализ намерений вопроса: `question_processing.detect_intent()`. Сопоставление вопроса с понятием: `OntologySearch.resolve()`; при низкой уверенности система возвращает уточняющие варианты, а не засчитывает вопрос.
- Генерация ответа из определения и направленных отношений: `Ontology.response()` (правила, **без генеративной LLM**).

### Настройки

В боковой панели: выбор онтологии/тем, минимальное количество вопросов, глубина учебного DFS-маршрута и категория вопросов. В графе: 1, 2, 3 уровня или «Все понятия». В режиме «Все» показываются **все узлы и отношения**, включая несвязанные компоненты. Для крупных графов раскладка упрощается, чтобы избежать зависания браузера; подписи на полном графе могут перекрываться, используйте масштабирование и просмотр фрагментов.

### Тесты

```powershell
python -m pip install pytest httpx python-docx
python -m pytest -q
python tools/evaluate.py
```

Проверено в окружении разработки: 45/45 автотестов; 23/23 правильных сопоставлений на подготовленном наборе. Это демонстрационный набор, не независимый бенчмарк и не доказательство полного понимания естественного языка.

### Ограничения

- **Авторизация / владельцы онтологий и многопользовательские профили ещё не реализованы.** Загруженные онтологии сохраняются на текущем сервере и доступны пользователям этого экземпляра. Нельзя разворачивать проект публично, не добавив контроль доступа и ограничения загрузок.
- Учебные сессии сохраняются в памяти процесса: при перезапуске сервера активная сессия теряется. Загруженные онтологии остаются на диске.
- Проверка качества графа — структурная, логическая непротиворечивость предметных утверждений автоматически не доказывается.
- Формулировки ответов строго ограничены имеющимися определениями и связями.
- Для решения требования «любой компьютер без Python и pip» приложение надо развернуть на общедоступном сервере; входной интерфейс тогда остаётся только браузерным.

Исходники и источники: `app.py` (FastAPI), `graph.py` (онтология и QA), `question_processing.py` (NLP), `ontology_search.py` (поиск), `static/*` (HTML/CSS/JS, дизайн не менялся), `script.py` (DOCX → ONTOLIS), `sources/*` (исходные учебные данные).

# OntoTutor — интерактивная обучающая система на основе графа знаний

Локальное учебное веб-приложение на **Python / FastAPI + HTML / CSS / JavaScript**.
Пользователь выбирает предметную область (онтологию ONTOLIS), отмечает понятия, сам выбирает начальную точку первым вопросом и затем последовательно изучает ветку графа в глубину (DFS). Ответы строятся по узлам и связям онтологии — **без LLM, ключей API и платных сервисов**.

---

## 1. Быстрый запуск

Нужен **Python 3.10+**. Откройте папку `ontolis_tutor` в VS Code и выполните в терминале:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1          # если заблокировано — CMD: .venv\Scripts\activate.bat
pip install -r requirements.txt
uvicorn app:app --reload
```

Linux / macOS: `python3 -m venv .venv && source .venv/bin/activate`.

Откройте **http://127.0.0.1:8000**. Описание API — **http://127.0.0.1:8000/docs**. Остановить сервер: `Ctrl+C`.

Для более точной обработки русских падежей (необязательно): `pip install -r requirements-advanced.txt` (подключает `pymorphy3`).

## 2. Как пользоваться

1. **Выберите предметную область** в левой панели — или нажмите **«＋ Загрузить .ont»** (`.ont` / `.json`, до 5 МБ). Корректный файл появится в списке, приложение покажет число понятий, связей и определений.
2. Если в онтологии нестандартные названия связей, откройте **«Настроить типы связей»**, назначьте им учебные роли и нажмите «Сохранить роли связей».
3. **Отметьте понятия.** Это область допуска: отмеченное понятие и все его подтемы. Начальной точкой отметка не является.
4. Укажите **минимум вопросов** (1–100) и нажмите **«Начать обучение»**. Настройки блокируются.
5. **Задайте первый вопрос, явно назвав любое доступное понятие**, — оно станет началом ветки. Пример: отмечена «Клетка», можно начать с «Что такое митохондрия?».
6. Далее система ведёт по ветке в глубину. Вопрос о текущем понятии засчитывается и открывает следующий шаг; вопрос о другом узле ветки не засчитывается.
7. После последнего узла ветки снова можно выбрать любое доступное понятие (в том числе уже пройденное). Счётчик вопросов не сбрасывается.
8. **«Завершить»** доступно после минимума вопросов, но продолжать можно и дальше. **«Завершить досрочно»** — в любой момент.

Кнопки в шапке: **«Справка»** — пошаговая инструкция; **«Качество»** — проверка полноты и структуры графа.

**Формат файла.** Принимается текстовый JSON-экспорт ONTOLIS с массивами `nodes` и `relations`. XML/OWL, RDF, ZIP и двоичные файлы не распознаются. Ограничения: 1–1000 понятий, до 5000 связей, уникальные ID, непустые названия, связи — только на существующие понятия. Определение читается из `attributes.def` (поддерживаются также `Определение`, `definition`, `description` и др.); исходный файл не переписывается.

**Пример без своего файла:** `examples/biology_demo.ont` (7 понятий, 6 связей). Загрузите его, назначьте связи `contains → has` и выберите «Клетка» — получится маршрут «Клетка → Органоиды → Ядро → Митохондрия → Рибосома → Клеточная мембрана → Цитоплазма».

## 3. Учебный маршрут

### Два режима сессии

```text
Начать сессию → choose_start (маршрута нет)
   ↓ вопрос, явно называющий доступное понятие
learning_path([названное понятие]) → in_branch (обход DFS)
   ↓ вопросы по узлам ветки в нужном порядке
конец ветки → choose_start (можно выбрать новую точку)
```

- Узел вне выбранной области → ответ `out_of_scope`, вопрос не засчитывается.
- Вопрос не о текущем узле во время ветки → `out_of_order`, вопрос не засчитывается.
- Внутри ветки шаги не повторяются (в том числе при циклах); в новой ветке пройденные понятия выбираются заново.
- Вопрос «Что такое?» без названия начальный узел не определяет.
- Дополнительный вопрос по другой доступной ветке может быть объяснён без перехода и без зачёта, если не нарушает порядок.

### Роли связей

В исходных данных связи хранятся в смысловом направлении; для обхода от общего к частному часть из них инвертируется.

| Роль | Направление в данных | Что делает обход |
|---|---|---|
| `has` | целое → часть | идёт от целого к части |
| `a_part_of` | часть → целое | идёт в обратную сторону |
| `is_a` | вид → класс | идёт в обратную сторону |
| `is_instance` | экземпляр → класс | идёт в обратную сторону |
| `used_for` | средство → назначение | идёт к цели |
| `use` | субъект → используемое | идёт к используемому |
| `input` | ресурс → потребитель | идёт назад, ко входным данным |
| `output` | узел → результат | идёт по направлению |
| `same_as` | понятие → синоним | только показывается, шага не создаёт |
| `ignore` | любая | в маршрут не входит |

Роль назначается **всем связям с этим названием** в онтологии. Неверно назначенная роль даст неверный порядок — смысл связей определяется по онтологии, угадать его программа не может. Настройки хранятся в `data/ontologies/<id>/relation_mapping.json` (для исходной онтологии — `data/relation_mapping.json`) и применяются к **новым** сессиям; уже идущие сохраняют прежний граф.

### Порядок подтем

Порядок одноуровневых подтем в `.ont` не задан. Его можно указать в `curriculum_order.json` (у исходной онтологии — `data/`, у загруженной — `data/ontologies/<id>/`):

```json
{ "a": ["b", "c"] }
```

`a` — ID родителя, `b`, `c` — ID детей в нужном порядке. Файл меняет очередность только уже существующих связей. Остальные дети идут после них — по приоритету роли связи, затем по ID. После правки перезапустите сервер; в веб-интерфейсе ручная перестановка не реализована.

### Как строится ответ

Ответ начинается с определения понятия, затем добавляются проверяемые связи графа (состав, виды, назначение, входы/выходы, сравнение). Если данных нет, система так и говорит и ничего не придумывает. Вопрос разбирается правилами: нормализация, словоформы, синонимы, небольшие опечатки, определение типа запроса. Это **не семантический поиск**: нераспознанный вопрос нужно переформулировать.

## 4. Интерактивный граф

Кнопка **«Посмотреть граф связей»** (и кнопка под ответом) открывает окно с графом выбранного понятия.

- **Показаны все связи** между отображаемыми понятиями, а не только с центральным. Глубина — 1 или 2 уровня; лимит — 30 понятий и 150 связей (при превышении видно пометку «показана часть графа»).
- **Раскладка:** центральное понятие в середине, соседи вокруг, потомки хабов — веером за родителем; овалы не пересекаются. Если прямая стрелка проходит через чужой овал, она изгибается.
- **Цвет связи зависит от типа** (`is_a`, `a_part_of`, `has`, `use`, `input`/`output` …); легенда — над схемой. Тип подписан на стрелке.
- **Наведение** на овал приглушает всё, кроме его связей; **клик** открывает определение и список связей понятия справа; «Показать связи этого понятия» перестраивает граф вокруг него.
- **Масштаб:** колесо мыши, перетаскивание фона, кнопки «+», «−», «⤢» (показать всё). Работает без внешних JS-библиотек, офлайн.
- В самых плотных графах (≈25 понятий и 40+ связей) схема остаётся густой — используйте подсветку и масштаб.

## 5. Структура проекта

| Файл / папка | Назначение |
|---|---|
| `app.py` | REST API, загрузка онтологий, сессии, история, граф, качество |
| `graph.py` | Узлы и рёбра, роли связей, DFS-маршрут, подграф, формирование ответов |
| `question_processing.py` | Нормализация, словоформы, синонимы, тип вопроса |
| `static/index.html`, `styles.css`, `app.js` | Интерфейс, стили, чат, SVG-граф |
| `data/ontology.ont` | Исходная онтология (не переписывается) |
| `data/ontologies/<id>/` | Загруженные онтологии: `ontology.ont`, `meta.json`, `relation_mapping.json`, `curriculum_order.json` |
| `examples/biology_demo.ont` | Демонстрационная онтология |
| `tests/` | Автоматические тесты (`test_app`, `test_v4`, `test_v5`, `test_multi_ontology`, `query_cases.json`) |
| `tools/evaluate.py` | Оценка поиска по размеченным вопросам |

Архитектура: браузер (`static/`) → FastAPI (`app.py`) → ядро графа (`graph.py`) и разбор вопросов (`question_processing.py`) → хранилище ONTOLIS (`data/`). Каждая загруженная онтология — отдельный объект; сессия хранит ссылку на свой граф, поэтому чужие настройки её не меняют.

## 6. REST API

| Метод и URL | Действие |
|---|---|
| `GET /api/ontologies` | Список онтологий и статистика |
| `POST /api/ontologies` | Загрузка файла (`multipart/form-data`, поле `file`) |
| `GET` / `PUT /api/ontologies/{id}/relations` | Типы связей и их роли (`{"mapping": {"contains": "has"}}`) |
| `GET /api/ontologies/{id}/quality` | Отчёт о качестве графа |
| `GET /api/ontologies/{id}/graph/{node_id}?depth=1` | Подграф (глубина 1–2) |
| `GET /api/meta?ontology_id={id}` | Понятия и статистика |
| `POST /api/sessions` | Создать сессию: `{"ontology_id", "selected_topics", "question_count"}` |
| `GET /api/sessions/{sid}` | Состояние (`mode`: `choose_start` / `in_branch`, `current`, прогресс) |
| `POST /api/sessions/{sid}/ask` | Вопрос: выбор начальной точки или шаг DFS |
| `GET /api/sessions/{sid}/history` | История вопросов и ответов |
| `POST /api/sessions/{sid}/complete` · `/force` | Обычное / принудительное завершение |

`ontology_id` необязателен (по умолчанию `default`). Ответ `GET .../graph/...` содержит `nodes` (с `level` — расстоянием от центра), `edges` и признак `truncated`.

## 7. Проверки

```powershell
pip install pytest httpx
python -m pytest -q
python tools/evaluate.py
```

Тесты покрывают исходный граф, DFS, запрет перескока, возврат к выбору ветки, загрузку и валидацию файлов, роли связей, независимость сессий, чтение с диска, тексты ответов и структуру подграфа. 23 размеченных вопроса в `query_cases.json` — небольшой демонстрационный набор, а не независимая оценка качества понимания русского языка.

> Последний полный прогон (39 тестов) выполнялся на версии 5.0. После правок дизайна и графа (v5.1–v5.3) интерфейс проверен в Chromium с имитацией API; полный `pytest` перед использованием стоит запустить заново.

## 8. Ограничения

- **Локальное приложение:** без аккаунтов и авторизации. Не публикуйте сервер в интернете без защиты и лимитов на загрузки. Максимум — 50 дополнительных онтологий.
- **Сессии и история хранятся в памяти** процесса и пропадают при перезапуске сервера (`localStorage` браузера хранит лишь выбранную онтологию и ID сессии). Для постоянного хранения нужен SQLite/PostgreSQL. Загруженные онтологии лежат на диске и сохраняются.
- **Нет LLM, RAG и векторного поиска.** Если ИИ использовался при разработке, в отчёте нужно привести реальные промпты — код их не хранит.
- Проверка качества выявляет структурные проблемы (определения, пустые и неразобранные связи, циклы `is_a`), но **не доказывает смысловую непротиворечивость**.
- Связи без названия (в исходной онтологии `231` и `236`: «Скорость обучения» → ЛР2 и ЛР6) в маршрут не входят: назначать им роль без подтверждения — догадка. Исправлять их следует в исходной онтологии.
- Рассчитано на небольшие учебные графы, не на промышленные.

## 9. История изменений

- **v5.3** — учебный диалог стал выше: сжаты шапка, строка статуса и карточки над чатом.
- **v5.2** — переработан интерактивный граф (раздел 4): все связи между отображаемыми понятиями, лимит подграфа 13 → 30 понятий, цвета по типам, подсветка при наведении, список связей в панели, масштабирование.
- **v5.1** — новый визуальный стиль «дашборд»: светлая рамка, скруглённые карточки, лавандовая палитра, тёмные градиентные карточки, штриховая полоса прогресса. Расположение блоков и логика не менялись.
- **v5.0** — новый интерфейс и овальный граф с подписями связей; удалён блок «Источники и путь по графу» (API источников сохранён); убраны служебные заглушки в ответах и имя онтологии в приветствии; отредактированы определения исходной онтологии (регистр после «это», узлы `65` и `208`); сведения о связях без названия объединены в проверке качества.
- **v4** — чтение вариантов атрибута определения, словоформы/синонимы/опечатки, типы вопросов, отдельное окно графа, строка состояния, история диалога, проверка качества данных, справка.
- **v3** — свободный выбор начальной точки первым вопросом и DFS-обход веток вместо жёсткого маршрута от первого отмеченного корня; режимы `choose_start` / `in_branch`; минимум вопросов стал порогом завершения, а не пределом.
- **v2** — несколько онтологий с загрузкой `.ont`, настройка ролей связей, изолированные сессии.

## 10. Что включить в отчёт

- **Архитектура:** схема из раздела 5.
- **DFD:** запрос и настройки пользователя → проверка и поиск понятий → выбор узлов и связей → формирование объяснения → ответ и обновление сессии.
- **Связь по управлению:** настройка → выбор стартового понятия → последовательность вопросов → следующая ветка или завершение; ошибочный вопрос счётчик не увеличивает.
- Можно ссылаться на API и результаты тестов, но не утверждать, что доказана логическая непротиворечивость системы.

# OntoTutor — интерактивная обучающая система на основе графа знаний

**Актуальная документация для версии 8.1.** OntoTutor — веб-приложение для изучения понятий и их взаимосвязей по онтологиям, созданным в [ONTOLIS](https://ontolis.com/). Пользователь выбирает онтологию и темы, задаёт вопросы на русском языке, получает определения и пояснения из графа знаний и самостоятельно перемещается между понятиями.

**Ключевой принцип:** предметные определения, понятия и связи **не зашиты в Python-коде**. Они берутся из выбранного файла `.ont`. Приложение рассчитано на замену онтологии без переписывания алгоритмов, если файл соответствует поддерживаемой структуре ONTOLIS.

## Возможности

- Загрузка и переключение онтологий ONTOLIS (`.ont` / JSON-экспорт), проверка их структуры и заполненности определений.
- Поиск понятий по полным названиям, словам в скобках, сокращениям, синонимам, словоформам, приблизительным совпадениям и тексту определений.
- Обработка вопросов о значении, назначении, составе, разновидностях, связях, входных/выходных данных, сравнении и принципе работы.
- Ответ в последовательности **«вопрос (как он понят системой) → определение → объяснение»**. Пояснения строятся из определений и направленных связей онтологии, а не из заранее подготовленных ответов по конкретной теме.
- Представление отношений в виде семантических троек **«субъект — предикат — объект»** с сохранением направления исходной связи.
- Свободное изучение графа: переход к родителю, дочерним и соседним понятиям, возврат назад или выбор другой темы в разрешённой области.
- Интерактивная схема с овальными узлами, подписями отношений, определением выбранного понятия и режимами **1, 2, 3 уровня / «Все»**.
- Настройка выбранных тем, минимального числа вопросов, допустимой глубины исследования и категории вопросов.
- Подсказки, состояние занятия, история переписки, обычное и досрочное завершение.

> **Важно:** это онтологическая QA-система с правилами обработки языка, **без генеративной LLM в процессе ответа**. Система не может достоверно ответить на вопрос, если необходимые сведения отсутствуют в выбранной онтологии.

## Быстрый запуск

### Windows

Для локального запуска требуется **Python 3.10+**. На первом запуске нужен интернет для установки зависимостей.

1. Распакуйте проект.
2. Откройте папку `ontolis_tutor`.
3. Запустите `start_windows.bat`.
4. Приложение откроется в браузере по адресу **http://127.0.0.1:8000**.

Скрипт запуска создаёт `.venv` при необходимости, устанавливает зависимости из `requirements.txt` и запускает локальный сервер.

### Ручной запуск

Из каталога `ontolis_tutor` выполните в PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python start_web.py
```

Для разработки с автоматическим перезапуском сервера вместо последней команды можно использовать:

```powershell
python -m uvicorn app:app --reload
```

На Linux/macOS активируйте окружение командой `source .venv/bin/activate` и используйте `python3` при необходимости.

**Если страница отображается без оформления:** убедитесь, что существуют `static/index.html`, `static/app.js` и `static/styles.css`. Откройте `http://127.0.0.1:8000/static/styles.css`: файл должен отдаваться без ошибки `404`. Затем обновите страницу сочетанием `Ctrl + F5`. В версии 8.1 исправлена неполная упаковка CSS из предыдущего патча.

## Как пользоваться

1. Выберите предметную область в боковой панели или загрузите собственную онтологию.
2. Отметьте начальные темы, задайте минимальное количество вопросов, глубину поиска и при необходимости категорию вопросов.
3. Нажмите **«Начать обучение»** и задайте вопрос о любом доступном понятии.
4. Изучите определение и пояснение. Спросите о связанном понятии, чтобы перейти к нему; при необходимости вернитесь к предыдущему.
5. Кнопка просмотра графа показывает отношения и определения. В режиме **«Все»** отображается полный загруженный граф, в том числе отдельные компоненты.
6. После достижения минимального числа зачтённых вопросов используйте обычное завершение. Досрочно закончить занятие можно в любое время.

**Навигация не ограничена жёстким порядком DFS.** Текущим считается последнее понятие, о котором пользователь задал зачтённый вопрос. DFS может использоваться для рекомендаций, но не определяет единственно допустимый следующий шаг.

**Глубина области обучения:** `0` — вся связная компонента выбранных тем; положительное число ограничивает радиус доступных узлов. При определении соседства учитываются оба направления рёбер, но в ответах сохраняется реальное направление отношения. Понятие за пределами области может получить справочный ответ, однако такой вопрос не засчитывается в занятии.

## Данные ONTOLIS

Поддерживается JSON-экспорт с массивами `nodes` и `relations`. Основной атрибут определения — `nodes[].attributes.definition`:

```json
{
  "nodes": [
    {
      "id": "1",
      "name": "Понятие А",
      "attributes": {
        "definition": "Понятие А — это пример определения из документа"
      }
    },
    {
      "id": "2",
      "name": "Понятие Б",
      "attributes": {
        "definition": "Понятие Б — это другое определение"
      }
    }
  ],
  "relations": [
    {
      "id": "3",
      "name": "is_a",
      "source_node_id": "2",
      "destination_node_id": "1"
    }
  ]
}
```

Пример показывает **минимальные поля**, используемые приложением; полный экспорт ONTOLIS может содержать координаты, пространства имён, историю и другие свойства. Для совместимости при чтении также распознаются прежние ключи определений `def`, `Определение` и `description`. При этом веб-приложение не обязано переписывать загруженный файл.

Распространённые типы отношений (`is_a`, `is_instance` / `is_instance_of`, `has`, `a_part_of`, `use`, `used_for`, `input`, `output`, `same_as` и др.) обрабатываются согласно назначенным ролям. Для неизвестных типов отношение остаётся доступным для просмотра и перехода, но его смысл при необходимости нужно уточнить в настройках **«Настроить типы связей»**. Универсального понимания произвольного имени отношения программа не гарантирует.

В демонстрационном файле, входящем в проверенную сборку 8.1, — **54 узла, 99 связей и 53 заполненных определения**. Это характеристика *этого конкретного файла*, а не ограничение приложения. Если вы обновили DOCX и заново импортировали определения, показатели вашей версии могут отличаться.

## Перенос определений из DOCX в `.ont`

Отдельный `script.py` переносит определения из таблиц Word непосредственно в атрибуты вершин ONTOLIS. Он **не содержит готовых предметных определений**.

В документе должна быть таблица со столбцами **«Понятие»** и **«Определение»**; столбец **«Категория»** помогает различать одноимённые понятия.

Установите зависимости импортёра:

```powershell
python -m pip install -r requirements-import.txt
```

Пример запуска из корня проекта:

```powershell
python script.py --ont "sources/ontology_without_definitions.ont" --docx "sources/definitions_original.docx" --out "ontology_updated.ont" --report "definitions_report.csv" --overrides "tools/definition_matches.csv"
```

Аргументы:

| Аргумент | Назначение |
| --- | --- |
| `--ont` (или `--json`) | Исходный `.ont`-файл |
| `--docx` | Word-документ с определениями |
| `--out` | Новый `.ont`-файл; путь должен отличаться от исходного |
| `--report` | CSV с результатами сопоставления |
| `--overrides` | Необязательный CSV с колонками `node_id`, `doc_term`, `doc_category` для разрешения неоднозначностей |

Если в документе у одного термина есть разные определения (например, как у метода и модели), импортёр, включённый в эту сборку, не угадывает выбор и помечает запись как `ambiguous`; необходимое соответствие можно указать через `--overrides`. **В CSV соответствий записываются только термин и категория, но не текст определения.**

При повторном запуске **найденное определение заменяет прежнее** в `attributes.definition`; старые ключи `def` и `Определение` удаляются для успешно сопоставленного узла. Если запись не найдена или неоднозначна, её существующие атрибуты не меняются. Связи онтологии импортёр определений не исправляет.

После обработки проверьте `definitions_report.csv` и откройте результат в ONTOLIS либо загрузите его в OntoTutor.

## Как устроен поиск и формирование ответа

Для **каждой загруженной онтологии** строится собственный поисковый индекс. Этапы NLP и поиска:

1. **Нормализация и токенизация:** приведение регистра, Unicode-нормализация, обработка `ё/е`, выделение слов и удаление несущественных символов (`question_processing.py`).
2. **Морфология:** лемматизация с `pymorphy3`; если модуль недоступен, применяется более простой резервный алгоритм.
3. **Варианты терминов:** полные названия, значимые части названий, текст в скобках, сокращения и атрибуты-синонимы, извлечённые из текущего графа (`ontology_search.py`).
4. **Ранжирование:** точные и частичные совпадения, `RapidFuzz`, сопоставление токенов, TF-IDF и косинусная близость. Более конкретные длинные названия не должны автоматически уступать короткому корневому термину.
5. **Учёт графового контекста:** близость к текущему понятию помогает различать кандидатов; при недостаточной уверенности выдаются варианты «Возможно, вы имели в виду…».
6. **Определение намерения:** тип вопроса распознаётся по лингвистическим правилам (`detect_intent`), после чего выбираются релевантные направленные семантические тройки (`ontology_reasoning.py`, `graph.py`).
7. **Ответ:** исходный/интерпретированный вопрос, определение выбранного узла, связное объяснение на основе соседних понятий и отношений. Определения из онтологии не обрезаются искусственно до 230 символов.

**TF-IDF — лексическое векторное представление, не нейросетевые эмбеддинги.** Опционально доступен поиск с `sentence-transformers` при установленной зависимости и указании *локального пути* к модели:

```powershell
python -m pip install -r requirements-advanced.txt
$env:ONTOTUTOR_EMBEDDING_MODEL = "D:\\models\\my-sentence-transformer"
python start_web.py
```

Без локальной модели этот механизм не используется. В штатном режиме генеративная языковая модель не вызывается, а содержательные утверждения берутся из онтологии. Результат зависит от полноты определений, корректности направлений связей и качества поставленного вопроса.

## Архитектура проекта

| Компонент | Назначение |
| --- | --- |
| `app.py` | FastAPI: загрузка онтологий, API, настройки и учебные сессии |
| `graph.py` | Чтение и проверка ONTOLIS, граф, связи, область обучения и ответы |
| `question_processing.py` | Предобработка русского текста и определение типа вопроса |
| `ontology_search.py` | Поисковый индекс, кандидаты и оценка сходства |
| `ontology_reasoning.py` | Извлечение направленных троек и объяснение на основе отношений |
| `static/index.html` | Структура интерфейса |
| `static/app.js` | Взаимодействие с API, чат и визуализация графа |
| `static/styles.css` | Внешний вид интерфейса |
| `script.py` | Импорт определений из DOCX в атрибуты `.ont` |
| `data/` | Базовая онтология и конфигурации отношений/учебного порядка |
| `sources/`, `tools/` | Пример исходных материалов, соответствия и оценка поиска |
| `tests/` | Автоматические тесты |

Загруженные онтологии сохраняются сервером отдельно от базовой. Активные занятия и история их сообщений хранятся **в оперативной памяти процесса**: после перезапуска сервера они теряются; сохранённые файлы онтологий остаются.

## REST API

| Метод и путь | Назначение |
| --- | --- |
| `GET /` | Веб-интерфейс |
| `GET /api/ontologies` | Список доступных онтологий |
| `POST /api/ontologies` | Загрузка онтологии |
| `GET /api/meta` | Метаданные и доступные понятия |
| `GET`, `PUT /api/ontologies/{ontology_id}/relations` | Просмотр и настройка учебных ролей отношений |
| `GET /api/ontologies/{ontology_id}/quality` | Структурная проверка данных |
| `GET /api/ontologies/{ontology_id}/graph/{node_id}?depth=2` | Фрагмент графа (`1`, `2`, `3`, `all`) |
| `GET /api/ontologies/{ontology_id}/triples` | Направленные семантические тройки, с фильтрами `node_id`, `depth`, `limit` |
| `GET /api/ontologies/{ontology_id}/search?q=...` | Поисковые кандидаты без зачёта вопроса |
| `POST /api/sessions` | Начать занятие |
| `GET /api/sessions/{sid}` | Текущее состояние и доступные соседи |
| `GET /api/sessions/{sid}/history` | История диалога |
| `POST /api/sessions/{sid}/ask` | Обработка вопроса и обновление состояния |
| `POST /api/sessions/{sid}/complete` | Обычное завершение |
| `POST /api/sessions/{sid}/force` | Досрочное завершение |

В результате запроса к `.../ask` возвращаются данные ответа и перехода (`transition`: `start`, `neighbor`, `return`, `follow_up`, `topic_change`); при переходе к соседу — информация о фактическом ребре `traversed_via`. `out_of_scope` означает выход за разрешённую область: вопрос не засчитывается.

## Ограничения и безопасность

- **Нет авторизации и разграничения доступа к личным онтологиям.** Загруженные файлы доступны в рамках экземпляра сервера; перед публичным размещением необходимы дополнительные меры безопасности и контроль доступа.
- Нет постоянного хранилища истории и прогресса занятий: сессии теряются при перезапуске процесса.
- Неизвестные типы связей можно просматривать и использовать для переходов, но без описания их семантики не всегда возможно составить корректное объяснение.
- Проверки полноты и структуры графа **не доказывают** логическую непротиворечивость предметной области.
- Нейросетевые эмбеддинги необязательны, генеративной LLM нет; сложные перефразировки, нестандартные термины и вопросы без фактов в онтологии могут требовать уточнения.
- Локальный запуск требует установленного Python и зависимостей. Чтобы пользователь открывал приложение только по ссылке без установки, его нужно развернуть на сервере.
- Полноценный режим тестирования с автоматической оценкой правильных ответов отдельно от режима обучения в описанной сборке не реализован.

## Обновление проекта

Перед заменой файлов **сохраните резервную копию `data/` и своих загруженных онтологий**. Патч для версии 8.1 должен содержать **все три файла `static/index.html`, `static/app.js`, `static/styles.css`**: неполная замена папки `static` может привести к потере оформления. После обновления кода перезапустите сервер; сессии в памяти будут сброшены. Не заменяйте собственную обновлённую `.ont` устаревшей демонстрационной онтологией из архива.

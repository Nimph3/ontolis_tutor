# OntoTutor 3.0: пользователь выбирает начало ветки вопросом

## Что было не так в версии 2

После нажатия «Начать обучение» сервер сразу выполнял:

```python
steps = graph.learning_path(selected_topics)
```

Поэтому первым учебным шагом неизбежно становился первый отмеченный корень (либо первый из его обхода), хотя пользователь хотел начать с произвольного понятия. Все вопросы не о текущем узле отклонялись как нарушение порядка.

## Как теперь устроена одна сессия

**Чекбоксы выбирают область допуска, но не стартовую точку.** Если отметить родительское понятие, вопрос можно задать про любое его доступное дочернее понятие. Под «доступными» понимаются узлы, достижимые по учебным ролям связей, в том числе через сопоставленные вручную нестандартные отношения.

Состояние имеет два режима:

```text
Начать сессию
    ↓
choose_start (маршрут пуст)
    ↓ ученик задаёт вопрос, явно называя любое доступное понятие
Построить learning_path([названное_понятие])
    ↓ ответить по выбранному узлу
in_branch (продолжить обход DFS)
    ↓ вопросы по следующим узлам в нужном порядке
Конец ветки
    ↓
choose_start (можно снова выбрать любой доступный узел)
```

Когда первый узел сам по себе не имеет дочерних понятий, ветка заканчивается уже после первого ответа. Когда у него есть потомки, они последовательно изучаются в глубину. Внутри одной ветки шаги не повторяются, даже при циклических связях. В новой ветке ранее посещённые понятия можно выбрать заново.

### Пример

Отметили «Искусственная нейронная сеть» — значит, доступны она и её подтемы. Начали с вопроса «Что такое Слой нейронов?». Ветка будет построена из узла «Слой нейронов», а не из корня «Искусственная нейронная сеть». После завершения этой ветки можно начать изучение нейронной сети с самого корня или снова обратиться к любому доступному узлу.

### Ограничения и проверки

- Первый вопрос должен **явно назвать понятие**: «Что такое?» не определяет начальный узел.
- Если понятие не входит в выбранную область, сервер возвращает `out_of_scope` и не засчитывает вопрос.
- Если во время DFS задать вопрос по другому узлу, ответ будет `out_of_order` (без увеличения счётчика).
- Количество **засчитанных** вопросов накапливается через все ветки внутри одной сессии.
- Установленное число вопросов — **минимум для обычного завершения**. Это не максимальный предел. При достижении минимума можно завершить сессию, но продолжение разрешено. Принудительное завершение работает всегда.
- Поиск начального узла основан на совпадении названий понятий. Это **не** семантический поиск с языковой моделью: вопросы без распознаваемого названия нужно уточнять.

## Где реализовано

**`app.py`:** в `Session` отдельно хранится разрешённая область `allowed_nodes`, текущий маршрут `path`, индекс `position`, общий счётчик `answered` и число завершённых веток. Маршрут создаётся в обработчике `/api/sessions/{sid}/ask` при распознавании вопроса в режиме `choose_start`. В ответе `snapshot` сервер передаёт `mode`, `current` (или `null`) и прогресс конкретной ветки.

**`graph.py`:** метод `matched_node` умеет работать без текущего узла (`current_id=None`) и отдаёт предпочтение доступным узлам при одинаковых названиях.

**`static/app.js`:** обновлены тексты подсказок, переключение режима чата, индикация следующего шага и автоматическое уведомление о завершении ветки. Компоновка с увеличенным чатом сохранена.

**`tests/`:** автоматические тесты проверяют выбор глубокого дочернего узла первым вопросом, выполнение его ветки, недопущение перескока, возможность выбора новой ветки, ограничения выбранной области и продолжение после достижения минимального числа вопросов.
